- [ ] Store API key from the server and also the id of the gateway so that during offline control this node can only be accessed by the same gateway. This will prevent other gateways from controlling this node when the server is down.
- [ ] Implement a mechanism to update the firmware of the nodes over-the-air (OTA). This will allow for easy updates and bug fixes without needing to physically access the nodes. The OTA mechanism should be secure and should only allow authorized updates to be installed on the nodes. The OTA mechanism should also have a fallback mechanism in case the update fails, so that the node can revert to the previous firmware version. The OTA mechanism should also have a way to verify the integrity of the update before installing it, to prevent malicious updates from being installed on the nodes. The OTA mechanism should also have a way to schedule updates, so that updates can be installed at a convenient time (e.g., during low usage hours). The OTA mechanism should also have a way to notify the user when an update is available and when it has been installed successfully. The OTA mechanism should also have a way to roll back to a previous firmware version if the new update causes issues or is not compatible with the node.

The health monitoring mechanism should include features such as checking the battery level, signal strength, and uptime of the nodes. The health monitoring mechanism should also include a way to send alerts and notifications when certain conditions are met (e.g., battery level is low, signal strength is weak, node has been offline for a certain period of time, etc.). The health monitoring mechanism should also include a way to log the health and status of the nodes over time, so that trends and patterns can be identified. The health monitoring mechanism should also include a way to display the health and status of the nodes on the HMI display, so that users can easily see the status of their nodes at a glance.
